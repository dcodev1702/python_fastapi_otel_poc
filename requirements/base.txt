# FLOORS, NOT PINS: every line names the oldest release known to work. This file is what you EDIT; the file the
# image INSTALLS is requirements/lock.txt - the fully resolved, pinned set that `scripts/lock.sh` produces from
# this one inside the same python:3.14.7-slim base image the Dockerfile uses. That split gives you both things at
# once: newest-compatible packages when you *choose* to upgrade (`make lock-upgrade`, then review the diff), and a
# build that installs the same bytes tomorrow as it did today. The lesson behind it is already in the CHANGELOG
# (0.2.2): `openai>=1.80` let 3.x in overnight and every OpenAI span vanished until someone looked.
#
# The OpenTelemetry family must stay in lockstep - core 1.N.0 pairs with contrib 0.(N+21)b0, e.g. 1.44.0 <->
# 0.65b0 - and pip enforces that for you: the contrib packages pin opentelemetry-semantic-conventions to their
# exact matching version, so the resolver can only pick a consistent set. `pip check` in the Dockerfile confirms.
